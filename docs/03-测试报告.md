## 3. 关键验证记录

### 3.1 推广标志

```text
NotificationRecord(... pkg=com.dafeiyu.workisland id=1001 ...):
  flags=ONGOING_EVENT|ONLY_ALERT_ONCE|NO_CLEAR|FOREGROUND_SERVICE|PROMOTED_ONGOING
```

应用内：

```text
通知：开    实时更新：允许    电池：不优化
```

### 3.2 ColorOS 冻结证据

在后台等待时读取线程状态：

```text
/proc/<pid>/task/<tid>/wchan = do_freezer_trap
State: S (sleeping)
```

这解释了为什么应用内 `Thread.sleep(8000)` 不会按时醒来，也是把定时器搬到 driver 的直接原因。

### 3.3 并行轮次测试（T4）

1. 主任务 `rmvnszrdb6` 正在跑。
2. 通过 `/api/chat` 另起一条短任务（新会话）：`只回复两个字：好的`，返回 run `rmvnszrdb7`。
3. 等 12 秒，测试轮结束；`/api/state` 里只剩 `rmvnszrdb6`。
4. 岛上仍为「正在干活 / 正在处理…」，**没有**出现「任务完成」。

测试结束后临时会话已删除（进回收站）。

### 3.4 driver 守护（T5）

```text
driver1=9149
killed 9149
driver2=9515
```

终端里的守护命令：

```bash
while true; do node driver.mjs; echo "driver exited, restart"; sleep 2; done
```

## 5. 问题与修复记录

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 普通通知不上岛 | 缺少 ProgressStyle 与 promoted | 用 `Notification.ProgressStyle`，加 `android.requestPromotedOngoing` 与隐藏方法反射 |
| 2 | 完成后不收起 | 监听器跟着单轮 Claude 进程被收走 | 把监听搬进网关进程树（driver） |
| 3 | 定时器不生效 | ColorOS 后台冻结（`do_freezer_trap`） | 定时器搬到 driver；待机通知换 ID 1002 |
| 4 | 还在干活就报完成 | 把 `run` 当成 `runs`；换轮空隙 `run` 为空 | 看 `runs`；`run_end` 后 2.5s 复查；完成前 3s 宽限 |
| 5 | `am broadcast` 失败 | 应用 uid 跨用户限制 | 改 `am start-foreground-service --user 0` |
| 6 | 重装后首次更新失败 | 服务尚未就绪 | driver 对 `am` 失败重试两次 |

## 6. 未覆盖 / 限制

- **force-stop 后恢复**：无法在不结束当前会话的情况下测试；设计上依赖重开 cccodroid 后网关模块拉起 driver。
- **重启开机自启**：`BOOT_COMPLETED` 接收器已声明，但未实际重启验证；ColorOS 的自启动开关需要用户手动打开。
- **长时间 Doze**：只测了屏幕打开、后台 8 秒；未做 30 分钟以上的 Doze 测试。
- **并行多轮文案**：岛上的短句可能跟随最后触发的事件；收工判定仍以 `runs` 为准。
- **exported 服务伪造**：同机应用可以发 START/DONE，属于演示级安全，生产化需加签名权限。
- **自定义胶囊外观**：未做 OPPO UPK 卡片，胶囊由系统绘制。

---

## 7. 结论

在 ColorOS 16 / Android 16 上，工作岛能够稳定显示 Claude 的真实工作状态，并在任务结束后自动收起。核心的三个非显然问题（推广、冻结、收工判定）均已定位并有对应实现。剩余限制主要来自系统规则（force-stop、Doze、OEM 自启动），已在文档中明确。
